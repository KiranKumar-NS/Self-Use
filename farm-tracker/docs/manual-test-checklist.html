🧪 Farm Tracker — Manual Test Checklist

How to use this checklist

  • Follow the order. Later tests use data created by earlier tests (buyers → transactions → dues → sales…).
  • For each case: do the Steps in the app, confirm the Expected result on screen, then do the Verify checks on the other pages it should have rippled to. This is a pure black-box UI test — everything is confirmed from the screen; you never open a database or run a terminal command.
  • The app reads once and caches (~5 min). After an action, another page or tab shows the new value only once you navigate to it or reload — a briefly stale screen is not a bug. So for a Verify step, open/refresh that page before judging it. (The one thing that updates live across tabs is covered in module 17.)
  • Computed live (no stored list): Dues (receivables/payables), the dashboard rollups and Notifications are recomputed from your transactions — there is no separate ledger to keep in sync, so trust the numbers on screen. Notification dismissals are remembered only in this browser.
  • Menu names to know: loans live under sidebar item "Owe & Lent", schedules under "Reminders", user admin under Admin → "Users". On mobile the bottom bar shows Home / Txns / Loans / Stock / More.
  • Notifications compute once on app load — always RELOAD the app before checking the bell 🔔 for a new alert (see module 17 for why).
  • Tap ✓ for pass, ✗ for fail. Write what went wrong in the note box. Progress saves in this browser automatically.
  • When done (or when you find bugs), press Copy report and paste the result back to Claude to get fixes.
  • Before you start: use a test account you are OK adding data to (run through the cases in order on a reasonably empty app). Role and multi-tab cases (module 17, and the optional viewer/manager cases) need a second browser / incognito window and a second account that was already set up as viewer / manager — this checklist does not create those roles, it only checks the UI behaves correctly once they exist.
  • Cases marked optional need extra setup (a second user, a pre-set role, or waiting for dates) — skip if not practical.
